## 0. 세 줄 요약

1. **문제는 "포맷이 부족한 것"이 아니라 "구조가 파이프라인 중간에서 버려지는 것"이다.** PDF/DOCX는
   이미 지원되지만 인용이 `제목 / body / lines N-M`으로 붕괴한다 — 실행으로 재현 완료(§1).
2. **HWP는 두 개의 다른 문제였다.** 구형 `.hwp`는 사실상 유일한 파서가 AGPL이지만, **HWPX는
   ZIP+XML이라 표준 라이브러리만으로 파싱된다** — 신규 의존성 0. 설계는 이 비대칭을 축으로 삼는다.
3. **분류 자동화(추론)와 벌크 인제스트는 지금 하면 안 된다.** 파싱 실패는 시끄럽고 분류 실패는
   조용하다. 500건에 잘못된 기본값이 걸리면 아무도 모른다(§4).

## 1. 확인된 결함 — 실행으로 재현

### 1-1. PDF·DOCX 인용 붕괴 (구조 전달 계층)

`parsers.py:199-204`가 PDF/DOCX를 무조건 `"text/plain"`으로 매핑한다:

```python
def chunker_mime_type_for(mime_type: str) -> str:
    if mime_type in SUPPORTED_TEXT_MIME_TYPES:
        return mime_type
    if mime_type in SUPPORTED_BINARY_MIME_TYPES:
        return "text/plain"      # ← 여기
```

그러면 `parsers.py:68`의 `is_markdown`이 False가 되어 `_parse_markdown_heading`이 **한 번도
호출되지 않고**, `section_path`가 영원히 비어, `parsers.py:248`에서 문자열 `"body"`로 고정된다.

동일 입력으로 실측:

```
MARKDOWN  → citation = 취업규칙 / 취업규칙 > 제2조 근로시간 / lines 3-3
PDF/DOCX  → citation = 취업규칙 / body / lines 1-3
```

**이것은 문서 전체를 가리키는 것보다 나쁘다.** `lines 1-3`은 *추출된 텍스트 스트림*의 줄 번호여서
원본 PDF의 페이지·조항과 아무 대응이 없다. 사용자가 검증하러 원본을 열면 **찾아갈 좌표가 없다.**

**가장 중요한 함의**: 설령 변환기가 제목을 복원해 `# 제목`으로 내보내도, 청커는 입력을
`text/plain`으로 통보받으므로 그 `#`을 본문 글자로 삼는다. **변환 계층만 고쳐도 효과가 0이다.**
고칠 지점은 이 seam 하나다.

### 1-2. 왜 지금까지 안 보였나 — 측정이 이 경로를 지나지 않는다

`eval/harness/.../live_runner.py:54`가 모든 문서를 `"mime_type": "text/markdown"`으로 등록한다.
PoC 코퍼스 14건 전부 마크다운 제목을 갖는다.

> **`poc-hr-pilot-2026-08-13.md`의 `citation_pct = 100.0`은 마크다운 입력에서 측정된 값이며,
> 실제 부서가 올릴 PDF/DOCX/HWP에는 이전되지 않는다.** PoC가 증명한 ACL 통제는 그대로 유효하다 —
> 인용 *품질*의 적용 범위만 정확히 긋는 것이다.

테스트도 같은 사각지대다. `tests/test_parser_contracts.py:49`가 붕괴한 형태
(`"... / body / lines 1-3"`)를 **정상 계약으로 고정**해 두었다. 이 seam을 고치는 슬라이스는 이
테스트를 **의도적 계약 변경**으로 다뤄야 하며, 조용히 고치면 안 된다.

### 1-3. 열람등급이 잘못된 입력에 fail-open — **라이브 재현 완료**

`acl.py:22-23`의 `confidentiality_rank()`가 **모르는 값을 `confidential`(최고 등급)로 처리**한다.
문서 쪽에 적용되면 "모르면 가장 민감하게" = 안전하다. **사용자 쪽에 적용되면 "모르면 최고 권한"**
= 정반대다. 같은 함수를 양쪽에 쓴 것이 원인이며, **주체 쪽은 어디에서도 검증되지 않는다.**

같은 사용자·같은 그룹으로 열람등급 문자열만 바꿔 실측:

| 보낸 값 | 보이는 문서 | restricted 문서 |
|---|---|---|
| `internal` | 25건 | 차단 (정상) |
| `internal ` (뒤 공백 1칸) | **26건** | **노출** |
| `typo-xyz` | **26건** | **노출** |
| `""` (빈 값) | **26건** | **노출** |

현재 피해 범위는 제한적이다 — `confidential`은 전역 차단이고 그룹 검사도 살아 있어, 상한은
"이미 그룹에 속한 restricted 문서"다. 그러나 **SSO 연동 시(ADR-103) 사내 IdP가 보내는 등급
속성값 하나가 매핑에 없으면 그 값을 가진 전 직원이 조용히 승급한다.**

→ 작고 독립적이며 이 설계와 무관하게 **지금 닫아야 한다.**

### 1-4. 그 외 확인된 사실

- **50페이지 PDF 한도**(`parsers.py:15`)는 **조용한 파일럿 블로커**다. 취업규칙·사규집·안전보건
  매뉴얼은 50p를 흔히 넘고, 초과 시 `PDF_PAGE_LIMIT_EXCEEDED`로 거부된다.
- **`knowledge_sources.default_confidentiality_level`은 존재하지만 한 번도 읽히지 않는다.**
  등록·업로드 모두 호출자 입력을 그대로 쓴다. 설계돼 있는데 배선이 없는 죽은 기능.
- **`access_groups`에 어휘 검증이 없다.** 오타 그룹이 그대로 통과해 문서가 조용히 안 보이거나
  의도보다 넓게 보인다. 기밀등급은 검증되지만 그룹은 아니다.
- **`parser_profile`이 이미 존재하는데 아무도 읽지 않는다**(`schemas.py:129` → `job.config`에
  기록 → `run_index_job`이 무시). 프로파일 기반 설계를 여기 얹으려는 사람이 **없는 토대를 있다고
  믿게 된다.**
- **부분 스캔 PDF가 무증상으로 실패한다.** 표지·목차만 텍스트 레이어가 있으면 "비어 있지 않으므로"
  성공으로 색인되고, 실제 규정 본문은 검색되지 않는다. 탐지 신호가 전무하다.
- `owner_department` 하드코딩(`page.tsx:163`)은 **인가에 쓰이지 않는다**(`acl.py` 전수 확인).
  거버넌스·보고 메타데이터 오염이지 보안 결함은 아니다 — **다만 부서 기반 분류 자동화를 넣는
  순간 인가 입력으로 승격되고, 이미 `"Operations"`로 오염된 채다**(§4).

## 3. ERD 제안

### 3-1. 설계 원칙 — "부서별 프로파일"은 두 가지가 뭉친 말이다

- **포맷 → 텍스트 규칙은 파일 포맷의 속성(코드)**이다. PDF는 어느 부서가 올리든 PDF다. 핸들러
  선택을 부서 함수로 만들면 "HR의 PDF를 DOCX 핸들러로" 같은 오설정이 가능해진다. 더구나 핸들러
  이름을 DB에 넣으면 **행 수정이 코드 실행 경로를 바꾼다** — current-state §8이 금지한
  self-changing rules에 접근한다.
- **거버넌스 기본값(등급·그룹)과 제목 관례는 부서·소스의 속성(데이터)**이다.

**데이터로 만들 것은 부서마다 실제로 다르다고 관측된 것만.**

### 3-2. ERD

```
                    ┌──────────────────────┐
                    │ ingestion_profiles   │ ★신규
                    └──────────┬───────────┘
                               │ 1
              ┌────────────────┴───────────────┐
              │ 0..N                           │ 0..N
  ┌───────────┴──────────┐                     │
  │ knowledge_sources    │                     │
  │ + ingestion_profile_id│ ★신규 컬럼(nullable)│
  └───────────┬──────────┘                     │
              │ N                              │
  ┌───────────┴──────────┐                     │
  │ documents            │ (변경 없음)          │
  └───┬──────────────┬───┘                     │
      │ N            │ N                       │
┌─────┴─────┐  ┌─────┴───────────┐             │
│ index_jobs│  │ document_chunks │             │
└─────┬─────┘  └─────────────────┘             │
      │ 0..1                                   │
┌─────┴──────────────────────────┐             │
│ document_ingestions       ★신규 ├─────────────┘
│ (색인 시도당 1행, append-only)   │
└────────────────────────────────┘
```

**순변화: 신규 테이블 2개 + 신규 컬럼 1개. 기존 테이블 데이터 변경 0.**

### 3-3. `ingestion_profiles` (거버넌스 기본값 + 제목 관례)

핵심 필드만:

| 필드 | 목적 |
|---|---|
| `default_confidentiality_level` | 문서 등록 시 미지정이면 이 값 |
| `default_access_groups` (JSON) | **오타 발생 지점(문서별 자유 입력)을 제거한다** |
| `heading_convention` | **고정 enum**: `auto`/`markdown`/`korean-legal`(제N장·제N조)/`numbered`/`office-styles`/`none`. 규칙 엔진 아님 |
| `title_source` · `effective_date_rule` | 제목·시행일을 어디서 읽을지 |
| `min_structure_ratio` | 구조 복원 비율이 이 값 미만이면 경고 기록. **차단 아니라 신호로 시작** |
| `version` + `status` | 수정 이력·소프트 삭제 |

`owner_department`는 **의도적으로 FK가 아니다** — 부서 레지스트리가 없고, 부서 분류는 SSO가
가져올 자산이다. 여기서 로컬 부서 마스터를 만들면 PR #135에서 제거한 분기 신원 경로를 되살린다.

### 3-4. `document_ingestions` (계보 — append-only)

**`documents`에 컬럼으로 넣으면 안 된다.** 재색인 시 직전 값이 덮여 "구버전 규칙으로 색인된 문서
목록"을 영원히 잃는다. 0005가 휘발성 `status` 대신 durable flag를 도입한 것과 같은 논리다.

핵심 필드:

| 필드 | 목적 |
|---|---|
| `converted_mime_type` | **청커가 실제로 본 것.** 오늘이면 항상 `text/plain` — 이 컬럼 하나가 §1-1 붕괴를 쿼리 가능하게 만든다 |
| `converter_chain` | 버전 포함(`pypdf/6.13>text`). 변환기 버그 시 영향 문서 특정 |
| **`structured_chunk_count`** | **`section_path`가 비지 않은 청크 수. 이 설계에서 가장 중요한 숫자다** — 이 비율이 곧 인용 신뢰도 |
| `extracted_char_count` | 페이지 수 대비 낮으면 **부분 스캔 탐지** |
| `warnings` (JSON) | `NO_HEADINGS_DETECTED` · `LOW_TEXT_DENSITY` · `TABLE_FLATTENED` 등 |
| `applied_profile_snapshot` | 적용된 규칙 원본. **버전 번호만으로는 in-place 수정에 속는다** |

### 3-5. 의도적으로 만들지 않는 것

| 후보 | 판정 · 근거 |
|---|---|
| `departments` / `access_groups` 마스터 | **불가** — SSO/AD가 권위 소스. 로컬 신원 소스 재생산은 PR #135에서 제거한 실수의 반복 |
| `format_handlers` 레지스트리 | **불가** — 핸들러는 코드. DB화하면 §8 self-changing 규칙 |
| 프로파일 버전 테이블 | **과함** — `version` + 스냅샷으로 충분 |
| `documents.structure_recovered` 비정규화 | **거부** — last-write-wins를 뒷문으로 되살림 |

### 3-6. 마이그레이션

- 신규 리비전 `0006`, `down_revision = "0005_document_has_been_indexed"`. 분기 없음.
- **완전 가역** — 기존 행 데이터를 바꾸지 않으므로 downgrade 시 정보 손실 없음.
- SQLite 테스트 경로 때문에 `op.batch_alter_table` 필수.
- **백필 원칙: 실제 행에서 유도 가능한 값만 채우고 모르는 것은 조작하지 않는다.**
  `extraction_status`는 `'unknown'`으로 둔다 — **`'ok'`로 채우면 검증하지 않은 품질 주장이 되고,
  그건 "시스템이 스스로 문제없다고 말하는" 실패의 재생산이다.**
- **ERD 변경 자체는 재색인 불필요.** 다만 §1-1 seam 수정은 청크 경계가 바뀌므로 **재임베딩
  불가피**하다(우회 불가 — 벡터가 다른 텍스트를 대표하게 됨).

## 4. 보안 판정

전체 트랩 체크는 패널 원본에 있고, 여기서는 **판정과 그 이유**만 남긴다.

### 진행해도 되는 것 — 포맷 확장 (조건부)

인젝션 결함은 `유사도(답변, 공격자저작_컨텍스트)`이고 그 식에는 MIME 타입이 없다. 정규화는 결함을
**깊게 하지 않는다.** 이걸 이유로 포맷 작업을 막는 것은 **실재하는 결함을 무관한 작업의 거부권으로
쓰는 것**이며, 보안 판단이 아니다.

**다만 정규화는 한 가지를 실질적으로 바꾼다: 사람의 눈을 없앤다.** 오늘 `.txt`/`.md`에서는 주입
문구가 업로드하는 사람에게 **보인다.** 그 육안 확인이, 약하고 기록되지 않을지언정, **오염 문서를
잡을 수 있는 시스템 내 유일한 통제**다 — `guard_input`은 청크 본문을 못 보고, 근거 가드는
구조적으로 무력하며, 인용 검증은 항상 통과하고, 판정자는 생성 전에 돈다.

DOCX 흰 글씨, XLSX 숨긴 시트, PPTX 발표자 노트, HTML 주석, PDF 투명 텍스트 레이어 —
이 전부에서 **작성 프로그램에는 안 보이고 추출기에는 보인다.** 관리자가 "검토한" 문서와 색인된
문서가 다르다.

**따라서 조건**: 어떤 포맷의 핸들러가 *렌더링되지 않는 위치에서 추출한 내용이 있음*을 보고할 수
없으면 **그 포맷은 나가지 않는다.** 이것은 탐지와 human-in-the-loop 요구지 **인젝션 완화 주장이
아니다.** 오늘의 육안 확인과 동등한 수준을 회복하는 것뿐이다.

**"보이는 텍스트만 추출" 방식은 채택하지 않는다.** 레이아웃 엔진의 출력을 근사하게 되고, 우회
비용이 0이며(8pt 회색 각주, 3000행 시트의 마지막 행, 평범한 정책 문장으로 위장), 정상 각주·주석을
삭제하는 실제 손실이 있고, 무엇보다 **또 하나의 "통과" 배지를 만든다** — `security_finalcheck_pass`가
이미 한 번 치른 실패다.

### 하면 안 되는 것 — 분류 추론 (BLOCKER)

파일명·폴더·내용에서 등급·그룹을 **추론**하는 것은 금지한다. 그것들은 전부 파일을 만든 사람이
정하는 값이며, **내용이 통제하는 인가 입력**이다 — PR #66·#83·#92에서 이미 세 번 고친 confused
deputy와 같은 형태다.

**관리자가 감사되는 경로로 설정하는 부서별 기본값은 허용**되며, 생산성 이득의 대부분을 준다.
단 다음을 만족해야 한다:

1. **제한 방향으로만 단조** — 자동화는 좁히고 올릴 수만 있고, 넓히거나 낮출 수 없다. 규칙이
   발동하지 못하면 **가장 제한적인 기본값**이어야 한다(오늘 업로드 기본값인 `internal`/
   `all-employees`가 아니라).
2. **산출물에서 유도 금지** — 파일명·폴더·내용은 안 된다.
3. **활성화 전 문서별 명시 확인** — 적용 후 보고가 아니라, 보여주고 확인받는다.
4. **`classification_source` 기록** — 왜 이 ACL인지(수동/규칙ID/기본값). 없으면 "깨진 규칙이 건드린
   문서"를 특정할 수 없다.
5. **집합 단위 되돌리기** + 벡터 재적재.
6. **저장된 필드가 아니라 실효 접근으로 검토** — "이 문서를 누가 읽을 수 있나"는 계산이고, 그걸
   답하는 엔드포인트가 없다. 없으면 벌크 승인은 형식일 뿐이다.

**왜 이게 파싱보다 위험한가**: 파싱 실패는 시끄럽고 선형으로 늘어난다. 분류 실패는 **노출은 선형으로
늘고 탐지 가능성은 반비례로 준다** — 500건이 전부 틀리면 그 corpus가 일관돼 보이고, 오히려 맞는
것이 예외처럼 보인다. 그리고 감사 로그는 결정을 *기록*할 뿐 *평가*하지 않으며, `denied_count`는
과잉 제한만 세고 과소 제한은 절대 세지 않는다. **누출은 결과가 더 많아지는 것이라 제품이 잘
동작하는 것처럼 보인다.**

### 하면 안 되는 것 — 벌크 인제스트 (BLOCKER, 같은 Work Order 금지)

`batch`·`dry_run`·스냅샷 세대 전부 저장소에 **0건**이다. 복원은 벡터를 다시 채우지 않으므로
보관을 되돌리기로 쓸 수도 없다. 배치 식별자·드라이런·단계적 활성화·집합 단위 되돌리기 없이
벌크를 넣으면, 위 모든 위험이 **복구 가능에서 불가능으로** 바뀐다. 그리고 벌크에서는 인젝션
결함이 **분리 불가능해진다** — 500건을 한 번에 넣으면 사람의 눈이 포맷 때문이 아니라 구조적으로
사라진다.

### 지금 닫아야 하는 것

- **열람등급 fail-open(§1-3)** — 작고 독립적, SSO 경로에 정확히 놓여 있음
- **선언된 타입으로 핸들러 분기** — `Content-Type`을 먼저 믿고 매직 바이트를 안 본다. HWPX도 ZIP,
  DOCX도 ZIP이라 핸들러가 늘수록 혼동이 커진다
- **압축 해제 크기 상한** — DOCX ZIP 읽기에 확장 크기 제한이 없다(코드 읽기 기준, **미재현**).
  OOXML/HWPX 3종을 추가하면 이 구멍이 4배가 된다
- **락파일이 설치 경로가 아니다** — `uv.lock`에 843개 해시가 있는데 Dockerfile과 CI는 느슨한
  범위로 재해석한다. **검토한 버전이 설치되지 않으면 라이브러리 심사는 무의미하다**

## 5. 반입 가능성 (폐쇄망)

| 형식 | 판정 |
|---|---|
| CSV | 표준 라이브러리. 의존성 0 |
| XLSX · PPTX · HTML | openpyxl · python-pptx · bs4 — **전부 MIT, 순수 파이썬**. 휠만 담으면 끝 |
| **HWPX** | **ZIP + XML(OWPML). 표준 라이브러리로 파싱 가능. 신규 의존성 0, AGPL 회피** |
| 구형 `.hwp` | `pyhwp`가 사실상 유일한데 **AGPL-3.0**, PyPI 최신이 **2020년**, 미해결 이슈 87개 |
| 스캔 PDF OCR | pytesseract + `tesseract-ocr-kor`. apt 미러링 1회. **동기 색인으로는 무리 — 비동기 큐를 강제한다** |

**반입 금지 판정**: Tika(JVM + **기본 설정에서 실행마다 jar를 인터넷에서 받아옴**),
EasyOCR·PaddleOCR(첫 실행에 모델 가중치 다운로드), PyMuPDF(AGPL/상용 이중, `pypdf`로 충분).

**구조 모델 권고**: docling의 **타입 트리 → 마크다운 직렬화** 패턴을 *라이브러리가 아니라 구조로*
채택. 형식별 백엔드가 제목·표·문단을 타입 노드로 만들고, 마크다운은 그 트리의 뷰. 우리 청킹이
heading 경계 기반이라 이게 유일하게 맞는 모델이다.

**어떤 변환 라이브러리도 인젝션 방어를 하지 않는다** — unstructured·docling·markitdown 전부 0건.
markitdown은 문서에 *"sanitization은 호출자 책임"*이라고 명시한다. OWASP RAG 치트시트가 색인
시점 스캔을 권고하지만 **구현체가 없다. 우리가 만들어야 하는 통제다.**

## 6. 순서 — "관리자가 전사 파일럿을 운영 가능한 최소 집합"

| 단계 | 내용 | 파일럿 필수 |
|---|---|---|
| **S1** | **계측 먼저** — `document_ingestions` + 관리자 화면 신호. **포맷을 하나도 안 늘린다** | ✅ |
| **S2** | 거버넌스 기본값 배선 — 이미 있는 `default_confidentiality_level` + `default_access_groups`. **가장 값싼 큰 승리** | ✅ |
| **S3** | 구조 충실도 — seam 재설계 + DOCX 스타일 + `korean-legal` 규칙. **PDF는 제외**(§7) | ✅ |
| **S4** | **HWPX 지원** — 표준 라이브러리. 구형 `.hwp`는 운영 절차로 | ✅ |
| S5 | `ingestion_profiles` 테이블 — **3번째 소스에서 규칙 복제가 시작될 때** | 파일럿 중 |
| S6 | 50p 한도 재검토 + 부분 스캔 탐지 — **S1 데이터를 본 뒤 숫자를 정한다** | 파일럿 중 |
| S7 | XLSX/CSV 표 표현 — 해당 부서가 실제로 요청할 때만 | 필요 시 |

**S1이 첫 번째인 이유**: 지금 PDF/DOCX를 올리면 인용이 조용히 붕괴하고 관리자는 알 방법이 없다.
구조 복원 없이 HWP를 먼저 추가하면 **무증상 실패를 곱하기만 한다.**

**S5를 뒤로 미루는 이유**: 소스가 적은 초기엔 컬럼이 프로파일보다 싸다. 마이그레이션 경로는
설계상 열려 있다.

## 7. 미확정 — 추정을 사실로 적지 않는다

1. **DOCX 제목 복원 가능성** — 한국어판 Word 실제 파일에서 `paragraph.style`이 `Heading1..9`로
   안정적인지 **미검증**. 한국 실무 문서는 스타일 없이 굵게·크기로만 제목을 표현하는 경우가 흔해
   **S3가 부분 성공에 그칠 가능성이 실재한다.**
2. **PDF 구조 복원** — 검증하지 못했다. S3에서 PDF를 제외한 이유다.
3. **HWPX 파싱 세부** — 구조는 외부 출처로 확인했으나 **실제 HWPX 파일로 실행해보지 않았다.**
4. **DOCX 압축 해제 폭탄** — 코드 읽기 기준. **재현하지 않았다.**
5. **HWP 라이브러리의 제목 보존 여부** — 후보 3개 전부 문서만으로는 확인 불가. **실제 사내 HWP
   파일 5~10건으로 시간 제한 스파이크가 필요하다.**

## 8. 다음에 결정할 것

- **구형 `.hwp` → HWPX 변환을 운영 절차로 수용할지** — 조직 결정. 코드로 고정하면 안 된다.
- **OCR을 파일럿 범위에 넣을지** — 넣으면 비동기 큐가 강제된다.
- **역할·권한 정본 문서** — 이 설계의 모든 것이 "누가 무엇을 할 수 있나"에 걸려 있는데, 그걸
  정리한 문서가 없다. 데모 역할 스위처(`admin`/`developer`/`finance`/`hr`)와 실제 역할
  (`PRIVILEGED_ROLES`={admin, platform-admin, knowledge-manager},
  `AUDIT_READ_ROLES`={admin, platform-admin, security-auditor})이 **일치하지 않아
  `knowledge-manager`·`security-auditor`를 화면에서 시연할 수 없다.**
